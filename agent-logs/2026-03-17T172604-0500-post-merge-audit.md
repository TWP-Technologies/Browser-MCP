## Audit notes
- Verified the stricter `element_ref` replay path now fails closed instead of falling back to first-match selector replay.
- Verified `browser_network_requests action=list` strips cached response body fields.
- Verified lazy response-body loading is MIME-gated before `Network.getResponseBody`.
- Identified one concrete contract leak in `browser_network_requests action=details`: the returned nested `request` object is the live internal store entry, so cached fields like `response_body` / `response_body_base64` can leak after a details call.
- Identified one remaining ergonomics risk: `browser_snapshot` and `browser_lookup` still emit `element_ref`s unconditionally, even when no explicit replayability check is performed before emitting the handle.
- Confirmed the in-memory bridge tests currently exercise fail-closed stale refs, but do not cover the live-extension case where a newly emitted handle is non-replayable from the start.

- Added integration and roundtrip E2E coverage for both behaviors.
